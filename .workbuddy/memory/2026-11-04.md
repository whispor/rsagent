# 2026-11-04

## 对照 pi-agent 优化 RsAgent + 补全自用功能

**背景**：用户指令「对比 pi-agent 进行优化」。pi-agent（`@earendil-works/pi-agent-core`）是三层架构中 `rsagent-agent` 的对标物。

### pi-agent 对齐（`rsagent-agent` 重写）

- **新增 `cancel.rs`**：`CancelToken`（`Arc<AtomicBool>` + `Arc<Notify>`），`new/cancel/is_cancelled/cancelled/reset`，廉价 Clone。每次 `prompt`/`continue_run` 开头 `reset`。
- **新增 `approval.rs`**：`#[async_trait] Approver { approve(tool_name, args) -> bool }` + `AllowAll`/`DenyAll`。`Agent::with_approver`。
- **`tool.rs`**：`ToolContext { cwd, progress: Option<UnboundedSender<String>>, cancel }`；新增 `ToolResult { content, details, terminate }`（对齐 pi 的 `AgentToolResult`）；`Tool` trait 增 `label()`、`is_sequential()`、`requires_approval()`。
- **`tools.rs`**：5 个工具改返回 `ToolResult`；写/改/bash 的 `requires_approval()=true`；`BashTool` 支持超时（默认 120s）+ `Stdio::piped` 流式逐行转发进度 + `tokio::select!` 处理 cancel/timeout/wait。
- **`agent.rs`**：新增 `steering`/`follow_up` 队列、`is_streaming`、`last_error`、`pending_tool_calls`、`abort()`、`cancel_token()`、`steer()`、`follow_up()`、`continue_run()`；`run_tool_calls` 先顺序 preflight（emit start + 审批）再按 `is_sequential` 决定 `join_all` 并行或顺序；`stream_turn` 用 `tokio::select! { biased; cancel; stream.next() }`；工具结果超 `MAX_TOOL_RESULT_CHARS=32_000` 截断。
- **`event.rs`**：`ToolExecutionStart` 加 `label`、`ToolExecutionEnd` 加 `details`、新增 `ToolApprovalRequest/Response`。
- **`main.rs`**：加 `-y/--yes`；`ApprovalMode{Auto/Ask/Deny}` + `CliApprover`；`run_prompt` 用 `cancel_token()` + `tokio::signal::ctrl_c()` 支持 Ctrl-C 中止；Renderer 渲染模型错误（`✗ model error:`）、token 用量、工具 label/进度。

### 补全自用功能（延续「全量实现」）

- **会话持久化**：`--session <FILE>`。`Agent::transcript() -> Context`、`Agent::load_messages()`；`main.rs` 加 `load_session`/`save_session`（JSON，`Context` 已 derive Serialize/Deserialize）。每次 prompt 后落盘，启动时若文件存在则恢复。
- **`.env` 加载**：新增 workspace 依赖 `dotenvy = "0.15"`；`main()` 在 `Cli::parse()` 前 `dotenvy::dotenv()`，使 clap 的 `env=...` 生效。
- **请求重试**：`StreamOptions` 新增 `max_retries`（默认 2，手写 `Default`）；`openai.rs` 抽出 `send_with_retry` + `is_retryable_status`（408/409/429/500-599）+ `backoff`（指数退避，封顶 8s）。仅在流开始前失败时重试；流中失败仍报 error 事件。

### 修复的 clippy 告警（pi 改动引入）

- `tools.rs` `stream_pipe`：`Ok(0)`/`Err(_)` 合并为 `Ok(0) | Err(_) => break`（`match_same_arms`）。

- `openai.rs::stream` 过长 → 抽 `send_with_retry`；`main()` 过长 → 抽 `run_repl`。

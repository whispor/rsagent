## rsagent 仓库合规 + CLI 完整性（用户："自己评估，按最优方案执行"）

自评结论：最高性价比的不是加新工具（webfetch 等风险更高、收益一般），而是**补齐仓库合规缺口 + 收敛 CLI 与库能力的落差**。

**改动**
1. **LICENSE**：新增 MIT 全文（`Cargo.toml` 与 README 早已声明 MIT，但仓库无该文件，导致 GitHub 不显示 license）。版权方写作 "rsagent contributors"。
2. **清理**：删除仓库根目录遗留的**空 `src/`**（未跟踪、无内容，易与 `crates/` 混淆）。
3. **CLI 新参数**（库早有对应能力，CLI 未暴露）：
   - `--max-turns <N>`：`value_parser!(u32).range(1..)`，默认 50，接 `Agent::with_max_turns`；传 0 被 clap 清晰拒绝。
   - `--temperature <F>`（`Option<f32>`）、`--max-tokens <N>`（`Option<u32>`）：接 `StreamOptions`，两个 provider 均已实际使用这两个字段。
4. **CI 加固**：clippy/test 加 `--locked`，确保使用已提交的 `Cargo.lock`。
5. **测试**：`cli.rs` 增至 6 项，新增 `--help` 列出参数、调参参数可正常接受、`--max-turns 0` 被拒、**`--help` 不泄露 env 值**（用 sentinel 值回归守卫上次的安全修复）。
6. **README**：CLI 表补三参数、Configuration 段补环境变量表、License 段指向 LICENSE。

**未做（附理由）**：未固定 `rust-toolchain.toml`——本机仅有 stable 1.99.1，钉具体版本会触发额外下载且需手工维护；edition 2021 的 rustfmt 输出稳定，CI 漂移风险很低，故保持 `@stable`。

**验收**：fmt 干净；`clippy --locked -D warnings` exit 0；`cargo test --workspace --locked` **31 项全过**；冒烟 `--faux --print`、`--version`、`--help` 正常。

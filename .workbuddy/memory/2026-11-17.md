## 项目重评估与「A→C→B」三批推进

**重评估结论**（实用性/易用性/简洁度）：分层干净、文档与工程化超出「最小实现」预期。真正值得动的是实用性缺口（读类工具无路径围栏、`read_file` 无行号、`thinking` 未接线）与一处简洁度冗余（`search`/`glob` 重复遍历）。方案分三批：**A 速赢 → C 整洁 → B 稳健与安全**，用户选择「全部按优先级推进」。

**关键发现**：`StreamOptions.thinking` **声明但从未被 provider 读取**（所有 `thinking` 引用都在解析响应侧）。故 B3「`--thinking` 参数」若只加 CLI 就是空开关——必须同时改两个 provider 的 `build_request_body`（纯函数、可单测）。B3 成本由「低」升为「中」。

### A 批（已实现，速赢）

1. **REPL 行编辑与历史**：引入 `rustyline`（`default-features = false`，仅核心编辑 + 内存历史）。新增 `src/input.rs`：**单线程独占 stdin**，REPL 与审批共用（避免两个 reader 抢字节）。stdin 为终端时用 rustyline；为管道时**回退到朴素 `read_line`**，故管道输入（测试、脚本）行为不变。异步接口用 `mpsc`(请求) + `oneshot`(回复)。`Recall::{Remember,Forget}` 区分是否入历史（REPL 入、审批不入）。
2. **`read_file` 行号 + `offset`/`limit`**：每行前缀 `{n:>width}\t`，右对齐；越界/空文件给明确提示；范围读取加脚注 `… (showing lines a-b of N)`。
3. **会话版本号 + `--continue`**：`SessionFile { version, context }` 信封，`SESSION_VERSION = 1`。加载时先解析为 `Value`，有 `version` 键按新格式（`>1` 则 `bail!` 拒绝而非误读），否则按旧的裸 `Context` 兼容。`--continue` = `--session .rsagent-session.json`。
4. **`NO_COLOR` / `--no-color`**：新增 `src/render.rs` 的 `Palette`（`ColorChoice::{Auto,Never}`），非 TTY 自动关色；`Palette::paint` 统一上色。抽出 `render_thinking_delta`/`render_text_delta`/`render_stream_error`/`print_approval_prompt`，把 `Renderer::render` 压到 100 行以内。

**踩到的项目约定（重要）**：`clippy.toml` 设 `max-fn-params-bools = 0`——**任何 bool 函数参数都会告警**，必须改用枚举（`Recall`、`ColorChoice`）。`struct_excessive_bools`（阈值 3）对 `Cli` 触发，用 `#[expect(..., reason = "...")]` 显式豁免（项目用 `expect` 而非 `allow`，且必须带 reason）。`doc_markdown` 要求 `NO_COLOR` 加反引号。

## 拓展性规范化：规范文档 + 可执行一致性测试 + 三平台 CI（用户 4 项要求）

用户提出四条：①功能拓展性（要重点评估）②工具拓展性（MCP/Skill/本地/网页统一对接、易装易卸、故障自愈）③平台适配（Win/Mac/Linux 稳定 + 兼容性）④对照主流产品的规范性优化；并要求不违背 5 条北极星与 BeautifulRust。

**核心评估结论（写进 `docs/EXTENSIBILITY.md` §2.1）**：**不做组件框架**。真正的成本在"边界"不在"抽象"；缺的是(a)不知道改哪些文件 (b)不知道哪些不变量不能破 (c)没法在评审前自证。因此组件化 = **配方 + 一条被强制的缝 + 一致性测试**。明确否决三案：动态库插件（`cdylib`+ABI 抬高门槛，违背③）、DI 容器（抽象数 > 扩展点数，违背①）、强行统一成一个 trait（`Tool` 与 `Provider` 问题不同）。

**新增 `docs/EXTENSIBILITY.md`（约 380 行）**：0 前提与三案否决 / 1 现状盘点表 / 2 功能拓展性（评估 + 四步流程 + 各类型配方表 + 10 条 MUST 不变量 + 一致性测试）/ 3 工具拓展性（`ToolSource` trait 设计 + 6 类来源taxonomy表 + `rsagent.toml` 配置 + 命名冲突与 `prefix` + 熔断器 + `rsagent tools` 子命令）/ 4 平台适配（差异集中到 `platform.rs`、6 个差异点表、5 条已知陷阱、CI 矩阵）/ 5 对照主流产品 9 项缺口表 / 6 P0–P3 路线图（每项标注对北极星①的影响）/ 7 决策记录 D1–D7 / 8 PR 检查清单 / 9 see also。约定：MUST/SHOULD/MAY + 每节英文摘要、中文正文。

**关键设计决策（D2/D3）**：`ToolSource` 在**装配期**由 `ToolCatalog` 展开成扁平 `Vec<Box<dyn Tool>>`，**`Agent` 完全不知道它的存在** —— 避免连接失败/超时等来源状态渗进核心循环。扩展隔离靠**子进程**而非同进程 ABI（与 MCP 设计取向一致）。熔断器**只统计"连接类"失败**，不统计业务失败（否则总报错的工具会熔断掉整个来源，掩盖真问题）。

**新增 `crates/rsagent-agent/tests/tool_conformance.rs`（7 个测试）**：把 §2.4 可机检部分固化——名称唯一且 snake_case、描述/标签非空、参数是 object schema 且 `required` 键已在 `properties` 声明、有副作用的工具必须 `requires_approval`（write_file/edit_file/webfetch/bash）、只读工具必须**不**要求审批、写盘/执行类必须 `is_sequential`、内置工具集与文档一致。**新增内置工具会自动被检查**——这是"规范"与"建议"的分界线。

**新增 `rustfmt.toml`（`newline_style = "Unix"`）**：缺它则 rustfmt 在 Windows 上写 CRLF、别处写 LF，`fmt --check` 会在某个 runner 上挂。加了之后 `cargo fmt` 把 7 个工作区文件从 CRLF 归一为 LF（`git diff` 显示**零内容变化**，git 已按 `.gitattributes` 归一化）。

**新增 `.gitattributes`**：`* text=auto eol=lf` + `*.bat/*.cmd eol=crlf` + 二进制标记 + `Cargo.lock linguist-generated`。验证未引发大规模重规范化（`git status` 仍只有 3 项）。

**CI 改三平台矩阵**：`os: [ubuntu-latest, windows-latest, macos-latest]`，`fail-fast: false`（一个平台红不应掩盖另外两个）。

**实测结果（重要）**：三平台 **全部 success**，fmt/clippy/test 每步都过。说明**代码本来就是跨平台干净的，缺的只是 CI 覆盖**——这直接满足③且是硬证据而非声明。

**验收**：Windows 本地 `cargo test --workspace --locked` **75 全过**（68 + 7 一致性）；clippy `-D warnings` exit 0；已推送 `bbaf2c6`，三平台 CI success。

## 项目重评估与「A→C→B」三批推进

**重评估结论**（实用性/易用性/简洁度）：分层干净、文档与工程化超出「最小实现」预期。真正值得动的是实用性缺口（读类工具无路径围栏、`read_file` 无行号、`thinking` 未接线）与一处简洁度冗余（`search`/`glob` 重复遍历）。方案分三批：**A 速赢 → C 整洁 → B 稳健与安全**，用户选择「全部按优先级推进」。

**关键发现**：`StreamOptions.thinking` **声明但从未被 provider 读取**（所有 `thinking` 引用都在解析响应侧）。故 B3「`--thinking` 参数」若只加 CLI 就是空开关——必须同时改两个 provider 的 `build_request_body`（纯函数、可单测）。B3 成本由「低」升为「中」。

### A 批（已实现，速赢）

1. **REPL 行编辑与历史**：引入 `rustyline`（`default-features = false`，仅核心编辑 + 内存历史）。新增 `src/input.rs`：**单线程独占 stdin**，REPL 与审批共用（避免两个 reader 抢字节）。stdin 为终端时用 rustyline；为管道时**回退到朴素 `read_line`**，故管道输入（测试、脚本）行为不变。异步接口用 `mpsc`(请求) + `oneshot`(回复)。`Recall::{Remember,Forget}` 区分是否入历史（REPL 入、审批不入）。
2. **`read_file` 行号 + `offset`/`limit`**：每行前缀 `{n:>width}\t`，右对齐；越界/空文件给明确提示；范围读取加脚注 `… (showing lines a-b of N)`。
3. **会话版本号 + `--continue`**：`SessionFile { version, context }` 信封，`SESSION_VERSION = 1`。加载时先解析为 `Value`，有 `version` 键按新格式（`>1` 则 `bail!` 拒绝而非误读），否则按旧的裸 `Context` 兼容。`--continue` = `--session .rsagent-session.json`。
4. **`NO_COLOR` / `--no-color`**：新增 `src/render.rs` 的 `Palette`（`ColorChoice::{Auto,Never}`），非 TTY 自动关色；`Palette::paint` 统一上色。抽出 `render_thinking_delta`/`render_text_delta`/`render_stream_error`/`print_approval_prompt`，把 `Renderer::render` 压到 100 行以内。

**踩到的项目约定（重要）**：`clippy.toml` 设 `max-fn-params-bools = 0`——**任何 bool 函数参数都会告警**，必须改用枚举（`Recall`、`ColorChoice`）。`struct_excessive_bools`（阈值 3）对 `Cli` 触发，用 `#[expect(..., reason = "...")]` 显式豁免（项目用 `expect` 而非 `allow`，且必须带 reason）。`doc_markdown` 要求 `NO_COLOR` 加反引号。

## P2-1 · `mcp-stdio` 来源（Model Context Protocol over stdio）

**新增 `crates/rsagent-agent/src/sources/mcp_stdio.rs`（约 950 行含测试）**
- 长驻子进程 + JSON-RPC 2.0 over stdio（一行一条 JSON、UTF-8、stdout 只走协议、日志走 stderr）。生命周期：`initialize`（client 发 `protocolVersion`/`capabilities`/`clientInfo`）→ server 回版本 + `capabilities`/`serverInfo` → client 发 `notifications/initialized`；再 `tools/list`（`nextCursor`/`cursor` 分页到尽）、`tools/call`。当前协议版本 `2025-06-18`（`MCP_PROTOCOL_VERSION`）。

## P2-2 · `mcp-http` 来源（Model Context Protocol over HTTP）

接着 P2-1 做第二项。这一步先做了一次**去重重构**，再加传输。

**重构：抽出 `crates/rsagent-agent/src/sources/mcp.rs`（共享载荷层）**
- 两种 MCP 传输只差"消息怎么送达"（stdin/stdout 管道 vs HTTP POST）；**线上载荷完全一样**——同样的 `initialize` / `tools/list` / `tools/call`、同样的工具描述符与 `content` 块。把这半边抽到 `mcp.rs`，谁都不独占：`MCP_PROTOCOL_VERSION`、`McpToolSpec`（含 `tool_spec()`）、`CallError{Transport,Protocol}`、`initialize_params()`、`parse_tools` / `parse_tool` / `parse_call_result` / `render_content` / `render_block`（后两个私有）。原 `mcp_stdio` 的 5 个解析单测移到这里（+1 只读注解用例）。
- 可见性：`mod mcp;` 私有；`MCP_PROTOCOL_VERSION` 用 `pub` 并经 `sources/mod.rs` `pub use` 再导出（与旧 `mcp_stdio` 同形，避开 `unreachable_pub`）；其余内部项用 `pub(crate)`。模块 doc 里跨模块链接写 `[`super::mcp::MCP_PROTOCOL_VERSION`]`（避免未在作用域的 intra-doc 链接）。

**新增 `crates/rsagent-agent/src/sources/mcp_http.rs`（约 600 行含测试）**
- **Streamable HTTP 传输**：向单个 `url` POST JSON-RPC；**接受两种响应编码**——`application/json`（单个 JSON 对象）或 `text/event-stream`（SSE，`data:` 载荷即消息），符合规范。子集仍是 `initialize` / `notifications/initialized` / `tools/list`（跟随 `nextCursor`）/ `tools/call`。
- `Endpoint{url,headers,timeout}`；`Connection{id,endpoint,client:reqwest::Client,session:Mutex<Option<SessionState>>,next_id:AtomicI64}`；`SessionState{session_id:Option<String>}`。`Accept: application/json, text/event-stream` + `MCP-Protocol-Version` 每请求都带；`Mcp-Session-Id` 仅在服务端于 `initialize` 响应头下发后才回带（`exchange` 从响应头读、`set_session_id` 记住）。`headers`（如 `Authorization`）叠加到每个请求。
- `exchange`：`tokio::time::timeout` 包 `send()` 与 `text()`；空 body（通常 202）视为通知回执；非空按 Content-Type 分派。`read_result` 把 JSON-RPC `error` → `Protocol`、id 不匹配 → `Transport`。`event_payloads` 解析 SSE body（剥 `data:` 前缀、按空行分事件），`find_event_response` 取 id 匹配的那条。
- 失败分类与 stdio 一致：**transport**（连不上/超时/非 2xx 且无 JSON-RPC error/body 不可解析）→ 熔断；**protocol**（合法 JSON-RPC error）或 `isError:true` → 不熔断。transport 失败即 `session=None`，下次调用重新 `initialize`。
- `McpHttpSource::new(id,url,headers,timeout)` 构造期即握手 + 列工具（坏端点加载期就失败 → 被跳过）；`with_breaker_policy`；`health()` 同 stdio。**注意**：HTTP 请求相互独立，故 `McpHttpTool` **不覆盖 `is_sequential`（默认 false）——允许并发**（与 stdio 因共享管道而顺序执行相反）。
- `SourceKind::McpHttp` + `as_str()→"mcp-http"`；`lib.rs` 导出 `McpHttpSource`。

**测试：进程内 mock HTTP 服务器**
- 单测里起一个 `TcpListener`（127.0.0.1:0），每连接读一个 HTTP/1.1 请求（请求行 + 头 + `Content-Length` body）、按闭包回一个 `Reply`、响应带 `Connection: close` 后关连接。`Reply::{json,sse,status,with_header}`。这样真实走 reqwest（含 HTTP/1.1 帧、SSE body、头），无需外部夹具。
- 10 个 mcp_http 单测：初始化/列/调用、SSE 响应、session-id 回带（记录器断言 `initialize` 无 session、`tools/list` 带 `session-42`）、额外头每请求都发、分页、`isError` 业务失败、JSON-RPC error 不熔断、不可达端点加载失败（`127.0.0.1:1`）、加载后 transport 失败开熔断、`event_payloads` 解析。
- `cli.rs` +1：不可达的 `mcp-http` 源被报告并跳过（`skipping tool source \`remote\``），运行仍成功。`config.rs` +1：`mcp-http` 的 `url`/`headers` 解析。

**踩坑（clippy）**：① 测试助手 `Request::reply(result: Value)` 触发 `needless_pass_by_value`（`json!` 宏对表达式是**借用**、不消费）→ 改用 `serde_json::Map` 显式 `insert` 消费；② `write_reply` 的 `head.push_str(&format!(...))` 触发 `format_push_string` → 拆成 `push_str` 分片 + 一次 `format!` 拼头部。

**验收**：fmt 干净；clippy `--all-targets --locked -D warnings` **exit 0**（仅 `os error 5` 锁噪声）；`cargo test --workspace --locked` **149 全过**（136 → 149：+10 mcp_http、+1 config、+1 CLI、+1 mcp 净增）。

## P2-3 · `skill` 来源（文件夹 + `SKILL.md` + `skill.toml` → 工具）

**目标**：把一个**文件夹**作为最小可打包单位——目录里有 `SKILL.md`（文档 + "这是技能"的标记）与 `skill.toml`（工具清单），每个 `[[tool]]` 指向一个脚本。与 `local` 的区别只在**工具列表从哪来**：`local` 问程序（`--describe`），`skill` 读清单，因此**不运行任何脚本**就能自描述、并在加载期完成校验。

- 新增 `sources/subprocess.rs`：`pub(crate) async fn run(argv, request: Option<&Value>, timeout) -> Result<String,String>`——spawn `argv[0]` + `argv[1..]`、可选写 stdin 后关管道、`tokio::select!{ child.wait() , sleep(timeout) }` 计时、两个 `tokio::spawn(read_all)` 抽干 stdout/stderr（防满缓冲死锁）、超时则 `kill().await`、非零退出报 stderr。`enum Outcome{Exited,TimedOut}`。`pub(crate) fn parse_response(&Value) -> Result<ToolResult,String>` 读 `{"content"|"error"}`（`details` 透传）。

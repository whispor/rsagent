## P2-4 · `web` 来源（HTTP 端点 → 工具）

**目标**：把**一个 HTTP 端点**包装成**一个工具**——最轻量的对接方式，无需改服务端，只要一个 URL。参数变请求、响应体变结果。

**设计要点**
- `WebSourceConfig { url, name, description, parameters, method, headers, requires_approval }`（`new(url)` 给默认：GET、无头、需审批、空参数 schema）；`WebSource::new(id, config, timeout: Option<Duration>)` **同步**（只建 `reqwest::Client`，不发请求）。
- 工具名缺省取来源 `id`；`parameters` 缺省 `{"type":"object","properties":{}}`。
- **请求构造**：`GET`/`HEAD` → 参数作**查询串**（字符串原样、其余 `to_string()` 成 JSON、`null` 丢弃）；其余方法 → 参数对象作 **JSON body**。`reqwest::Method::from_bytes` 解析方法（注意：`FETCH` 这类自定义方法是**合法**的 HTTP token，不会报错；只有含空格的非法 token 才报错——测试据此修正）。`headers` 每请求都带。
- **响应**：body 文本作 `ToolResult::text`；若可解析为 JSON，另存 `details`（给 UI/日志）。非 2xx → `Err("the endpoint returned HTTP {status}: {snippet}")`，`snippet` 取前 200 字符 + `…`。
- **失败分类（关键决策 D9）**：**只有 transport 错误**（连不上/超时/读响应超时）算连接类 → 熔断；**任何 HTTP 响应（含 4xx/5xx）都算业务失败** → `record_success`、不熔断。理由：HTTP 一旦应答就证明端点可达；若把 4xx 也判连接类，模型传错参数（400）会熔断掉整个来源。这与子进程来源"非零退出即连接类"**刻意不同**（子进程的非零退出往往是"根本跑不起来"）。
- `SourceKind::Web` + `as_str()→"web"`；`sources/mod.rs` 加 `mod web;` + `pub use web::{WebSource, WebSourceConfig};`；`lib.rs` 导出两者。

**接线**：`config.rs` 的 `SourceConfig` 加 `method`/`name`/`description`/`parameters`/`requires_approval` 五个可选字段（沿用"一个扁平结构覆盖所有 kind"的既有设计）；`main.rs` 的 `build_source` 加 `"web"` 臂（需要 `url`，逐个字段覆盖 `WebSourceConfig` 默认值），未知 kind 消息补 `web`。

**测试**：web 单测 +9（GET 查询串 / POST JSON body / null 丢弃 / 额外头 / HTTP 错误=业务失败 / 不可达开熔断 / 非法方法拒绝 / `scalar` / `snippet`）；`config.rs` +1（web 的 url/method/name/description/requires_approval/parameters 解析）；`cli.rs` +1（配置驱动的 web 源被列出，`[web]` + `wx__get_weather`；**加载期不联网**，URL 无需存活）。测试复用 mcp_http 的进程内 `TcpListener` mock HTTP 服务器写法。

**踩坑（clippy）**：无。仅一处测试假设错误：以为 `reqwest::Method::from_bytes(b"FETCH")` 会失败，实则自定义方法是合法 token → 测试改用含空格的 `"GET EXTRA"`。

**验收**：`cargo fmt --all --check` 干净；`cargo clippy --workspace --all-targets --locked -- -D warnings` **exit 0**；`cargo test --workspace --locked` **173 全过**（162 → 173：+9 web、+1 config、+1 CLI）。

## P2-5 · `--json` 输出（事件流 → JSON Lines）

**目标**：把 agent 的**事件流**按 JSON Lines 输出到 stdout，供 CI/脚本消费（`EXTENSIBILITY.md` §5 的 SHOULD 项）。

**关键决策（D10）：给事件类型直接 `derive(Serialize)`，不手写映射。**
- 先做了一次实证探针：**serde 的「内部标签」枚举确实支持 unit 变体**——`{"type":"unitOne"}`。这推翻了"必须手写 mapper"的预设（原以为内部标签不支持 unit 变体）。据此选择 derive。
- 手写映射会与枚举定义**漂移**（加一个变体就漏一个），违背⑤；derive 最省代码（①）且不可能漂移。复用 `ContentBlock`/`Message` 已有的 `type` 标签 + camelCase 约定，嵌套事件自然拼成同一形状。
- 三个类型：`AgentEvent`（rsagent-agent）、`StreamEvent` + `ErrorReason`（rsagent-ai）。属性统一 `#[serde(tag = "type", rename_all = "camelCase", rename_all_fields = "camelCase")]`；`ErrorReason` 是纯 unit 枚举 → 只需 `rename_all = "camelCase"`（序列化成 `"error"`/`"aborted"` 字符串）。
- 只加 `Serialize`，**不加** `Deserialize`（需求是输出；保持最小面）。

**CLI 接线**：
- `Cli` 加 `--json` 布尔标志。**`--json` 必须配合 `--print`**，否则**尽早**（在装配任何来源之前）`eprintln!` 报错并 `exit(2)`——理由是 JSON 流是给机器的一次性输出，与交互式渲染互斥。
- `OutputMode` 加第三个变体 `Json`。`render()` 开头 `if self.mode == OutputMode::Json { self.render_json(event); return; }`，`render_json` 用 `serde_json::to_string(event)` 打印一行；序列化失败（实际不会）打到 stderr 而非 panic。`progress_line` 的 match 加 `Json => {}`（抑制人读进度，保持 stdout 纯 JSON；注明当前不可达但保持穷尽）。`finish_prompt` 只在 `Interactive` 打空行，故 JSON 模式自然不追加空行。
- 退出码语义**不变**（模型级失败仍 `exit(1)`），脚本可同时依赖流与码。

**测试**：`cli.rs` +2——`json_emits_the_event_stream_as_json_lines`（逐行 `serde_json::from_str`，断言含 `agentStart`/`turnEnd`/`agentEnd`）；`json_without_print_is_rejected`（`--faux --json` 无 `--print` → 非零退出 + stderr 含 `--json requires --print`）。`help_lists_the_flags` 的 flag 列表补 `--json`。

**实测输出**（`--faux --print hi --json`）：`{"type":"agentStart"}` → `messageStart`(user) → `messageEnd`(user) → `turnStart` → `messageStart`(assistant) → 若干 `messageUpdate`（`textStart`/`textDelta`×N/`textEnd`/`done`）→ `messageEnd` → `turnEnd` → `agentEnd`。嵌套 message/stream 事件与顶层同形（camelCase + `type`），干净可 `jq`。

**踩坑**：无 clippy 告警。唯一要澄清的是 serde 内部标签对 unit 变体的支持（见上，用探针验证）。

**验收**：`cargo fmt --all --check` 干净；`cargo clippy --workspace --all-targets --locked -- -D warnings` **exit 0**；`cargo test --workspace --locked` **175 全过**（173 → 175：+2 CLI）。

**文档同步**：README CLI 表加 `--json` + 新增「JSON output」小节（事件顺序、`jq` 示例、退出码不变）；`EXTENSIBILITY.md` §5（机器可读输出行 ✅）、§6（P2-5 ✅）、§7 加 **D10**；`ARCHITECTURE.md` §4 补 `--json` 作为无头消费方的落地 + 测试数 173→175。

## P3-5 · 熔断器可观测 / 可重置 + `AgentEvent::SourceUnhealthy`（§3.5）

**目标**：兑现 §3.5 里唯一未竟的 MUST——「熔断器状态 MUST 可通过 `rsagent tools` 查询与手动重置」，并补上 P1 时因"没有消费者"而刻意延后的 `AgentEvent::SourceUnhealthy`。用户经选择确认走「熔断器可观测/可重置」这条。

**关键决策**
- **D12 · 用墙钟秒持久化，而非 `Instant`**：熔断器活在内存、随进程消亡；`Instant` 是单调时钟，跨进程无意义（新进程拿到的 `Instant` 无法与"现在"比，还原的剩余冷却必然错）。新增 `BreakerReport { state, failures, opened_at_unix, cooldown_secs }`（`#[serde(rename_all="camelCase")]`），`report()` 把 `Instant` 折算成 Unix 秒，`restore()` 启动时用当前墙钟反推 `opened_at`。
- **D13 · 健康探针是**不透明闭包**，而非让 `Agent` 持有 `ToolSource`**：一旦循环持有来源，它就得理解连接失败/超时/熔断等来源专有状态，D2 的隔离随之瓦解。`HealthProbe = Arc<dyn Fn() -> Vec<UnhealthySource> + Send + Sync>` 把来源健康降维成纯数据（id/kind/reason），循环只负责"对比上一轮、发一次事件"。CLI 侧用 `Arc<[SourceEntry]>` 同时供探针轮询与运行后快照（避免复制来源；clippy `rc_buffer` 要求用 `Arc<[T]>` 而非 `Arc<Vec<T>>`）。

**用户诉求**：先"再重新梳理整个项目，评估七维度"，再"直接逐项优化 A、B、C、D"。

**逐项优化（本轮完成 A–D）**
- **A · `AgentError::ModelFailed { message }`**：`error.rs` 新增变体；`agent.rs::run_turns` 把 `StopReason::Error` 与 `Aborted` 拆开——**Error → `Err(ModelFailed)`**，**Aborted 仍是 `Ok(())`**（用户主动中止不是失败）；`prompt`/`continue_run` 文档更新。CLI：`main.rs` 加 `is_model_failure()`（`downcast_ref::<AgentError>`），`--print` 分支改为先保存 session/breakers 再判定（ModelFailed → `exit(1)`，其余 `Err` 上抛）；REPL 遇 ModelFailed **吞掉并继续**（不让一次坏回合拆掉会话）。

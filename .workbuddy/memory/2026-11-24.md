### E1 · skill 的 `command` 可逃出技能目录（提交 `95a6ed0` + `40c7117`，测试 279 → 281）

**问题**：`skill.toml` 的 `command` 可以是绝对路径或含 `../..` 的相对路径，两者都不受技能目录
约束。复制一个 skill 目录过来（或 clone 一个含 skill 的仓库）＝获得「执行任意二进制」的能力，
且 `requires_approval` 默认由该 manifest 自己声明。

**实现**（`crates/rsagent-agent/src/sources/skill.rs::resolve_tool`）：在 `program.is_file()`
之后加 `canonicalize()` + `starts_with(root)` 约束。`canonicalize` 同时解掉符号链接，所以
「目录外软链」也一并被拒；文件不存在仍先报原来的清晰错误。**未新增任何依赖**。

**新增测试**（skill 模块 12 → 14）：
- `a_command_escaping_the_skill_directory_is_refused` —— `command = "../evil.sh"`，且目标文件
  **确实存在**（上一层），只有约束能拦住它 → 加载失败，错误含 `outside the skill directory`。
- `an_absolute_command_outside_the_skill_directory_is_refused` —— 指向目录外一个真实存在的
  绝对路径 → 加载失败。目录内的 `command = "run.sh"` 仍由既有测试覆盖正常加载。

**文档同步**（北极星 ⑤）：README「The `skill` source」的 `command` 注释改为
「resolved inside the skill folder」，并把「command 逃出目录」列入 load-time 校验清单；
`skill.rs` 模块文档同步改字。

### E3 · REPL 遇 `MaxTurnsExceeded`/`NoResult` 会退出且丢会话（提交 `19e81d1` + `18f2194`，测试 281 → 282）

**问题**：REPL 只容忍 `ModelFailed`；`NoResult` 与 `MaxTurnsExceeded` 落到 `return Err(error)`，
在**保存会话之前**就把循环拆掉——跑满 `--max-turns` 会静默丢弃整轮对话，与 README 第 585 行
「the interactive REPL never exits on a failed turn」**矛盾**。

**实现**（`crates/rsagent/src/main.rs`）：新增 `ends_the_session(&anyhow::Error) -> bool`，把容忍
判定从「是否模型级失败」改成「是否应当结束会话」。三个 turn 级错误（`NoResult` /
`MaxTurnsExceeded` / `ModelFailed`）都**不**结束会话；其余按**排除法**默认致命——这也是对
`#[non_exhaustive]` 枚举的安全方向（未来新增变体默认致命）。REPL 对**尚未**由事件报过的两个
（`NoResult`/`MaxTurnsExceeded`）打印「本轮未完成：…（会话已保留，可继续输入）」；
`ModelFailed` 仍由 renderer 报，不重复。`--print` 路径**未动**（所有失败运行仍退非零，符合 §6
退出码契约）；`is_model_failure` 保留（`--print` 仍在用）。

**新增 E2E**：`the_repl_survives_a_turn_that_hits_the_limit`（`tests/cli.rs`）——`--faux`
+ `--faux-tool read_file:{…}` + `--max-turns 1` + `--session`，stdin 依次喂 prompt 与 `exit`。
断言：进程退 0、stdout 含「本轮未完成」、会话文件含该 prompt。

**A/B 验证（决定性）**：把 `main.rs` 的修复 `git stash` 掉后重跑该测试 →
**FAILED，`ExitStatus(1)`**（旧行为：REPL 在 `MaxTurnsExceeded` 上直接退出，会话未保存）；
恢复后通过。证明这是真回归测试，而非恒真。

推送 E1 后核实 CI，发现 **`Audit` job 变红**（此前 `71f9977` 是 7/7 全绿）。这不是本轮改动
引入的——是**新发布的告警**。job 日志要 admin 权限（403），于是本地装 `cargo-deny 0.22.0`

改用 `cargo update -p url --precise 2.5.9` → `url 2.5.8 → 2.5.9` + `form_urlencoded 1.2.2 → 1.2.3`。
本地 `cargo deny check advisories` → **advisories ok**。Cargo.lock 只动这两个 crate。

### E2 · 外部输出无大小上限（提交 `cbaba0f` + `da59995`，测试 282 → 285）

**问题**：`search` 把每个命中文件**整份读进内存**再逐行匹配；`sources/subprocess.rs` 的共享
缓冲、`mcp_http.rs` 的 `response.text()` 同理——一个几百 MB 的文件 / 巨大的 MCP 响应就能把
进程内存推高。**已有的 32K 截断发生在完整缓冲之后**，对内存峰值没有任何约束（评审方特别
叮嘱：32K 是给模型的**上下文预算**，与本内存上限是两件事，**不要动它**）。

**实现**：给每条「外部输出读入」加 **8 MiB** 上限，超限一律**截断并标记**、不再累积：

- **`search`**（`tools.rs`）：读前先查 `metadata().len()`，超过 `MAX_SEARCH_FILE_BYTES`
  的文件**跳过不读**，把跳过的文件名逐条写进结果（`(skipped N file(s) larger than 8 MiB: …)`）。
- **`bash`**（`tools.rs`）与 **`subprocess.rs`** 的共享缓冲：边读边在 `MAX_OUTPUT_BYTES`
  处截断，回退到 UTF-8 **字符边界**（`is_char_boundary`，避免切出半个多字节字符），结果尾部
  追加 `… (output truncated at 8 MiB)`；`subprocess` 的 stdout 被截断时按**连接类**失败上报。
- **`web` / `mcp-http` / `webfetch`**：抽出**共享**的 `sources/http.rs::read_body`（新文件），
  用 `response.chunk()` 边收边卡上限。`web` 保留头部并标注 `… (truncated at 8 MiB)`；
  `mcp-http` 以连接类失败；`webfetch` 复用同一函数（原私有 `read_capped` 已并入）。
  三处调用方 > 一，符合北极星 ④「无两个调用方不加抽象」。

**新增测试（+3）**：
- `search_skips_files_larger_than_the_read_cap`（`agent_loop.rs`）—— 造一个 `CAP+1` 字节的
  稀疏文件（`set_len`，不占真实磁盘），在**文件开头**埋入匹配串；断言结果里出现小文件的命中、
  **不**出现超限文件的命中，且超限文件名出现在 `skipped` 标记里。
- `output_beyond_the_cap_is_dropped_and_flagged`（subprocess）、
  `command_output_beyond_the_cap_is_dropped_and_flagged`（bash）—— 断言超限输出被丢弃并打标。

**A/B 验证（决定性）**：把 `tools.rs` 的改动 `git stash` 掉后重跑 search 测试 → **FAILED**
（超限文件的命中出现，证明旧行为确实整份读入）；恢复后通过。

**文档同步**（北极星 ⑤）：README 的 `search`/`glob` 段、`bash` 表行、`web` 源、`local` 协议
四节均注明 8 MiB 上限与「截断/跳过并标记」的行为。
